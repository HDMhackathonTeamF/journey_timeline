## モック／実APIの切り替え

`frontend/.env`の`VITE_DATA_SOURCE`で切り替えます。

### モック

```env
VITE_DATA_SOURCE=mock
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

### 実API

```env
VITE_DATA_SOURCE=api
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

切り替え処理は`src/repositories/index.ts`にあり、画面側は同じ`JourneyRepository`インターフェースを利用します。

```text
React画面
  └─ JourneyRepository
      ├─ mockJourneyRepository → localStorage
      └─ apiJourneyRepository  → FastAPI
```

## 実装済みの主な新機能

### 1. 予定作成・編集時の時間自動計算
- 開始時刻、終了時刻、滞在時間（分）のうち2つが入力された時点で、残りの1つを自動算出・補完する機能を実装。
- 日時と分数の相互変換・加減算ユーティリティ（`addMinutesToInputDateTime`, `subtractMinutesFromInputDateTime`, `getDiffMinutes`）を追加。

### 2. 経路検索の出発・到着日時指定およびマルチモーダル探索
- 出発日時指定に加えて、「**到着日時**」からの経路逆算検索に対応。
- 誤操作や値の意図しない流用を防止するため、出発日時と到着日時の状態管理を完全分離し、ワンクリックで消去可能な「クリア」ボタンを配置。
- 選択された検索条件（出発 / 到着）に応じて検索ボタンの機能・ラベルが動的に連動。
- バックエンドの座標解決（`geo:lat,lon`）連携により、複数路線・乗換を跨ぐリアルタイム経路検索に対応。

### 3. PDF書き出し・印刷最適化
- ブラウザの印刷機能（`window.print()`）を活用した専用印刷レイアウトを実装（`@media print`）。
- A4縦サイズに最適化し、不要なUI要素の非表示やアイテムごとの改ページ制御を適用。

### 4. モード切替時のモーダル制御およびエディタのステート初期化保証
- **モード切替時の自動クローズ（1-A）**: 閲覧モード ⇔ 編集モードの切り替えを `useEffect` で検知し、エディタ・詳細パネルを自動クローズ（`setEditor(null)`）。
- **エディタ再マウントによるステート初期化（2-A）**: 各エディタコンポーネント（`EventEditor`, `TransitEditor`, `ItemDetail`, `JourneyEditor`）に一意な `key` プロパティを付与。別のアイテム選択や新規作成切り替え時にコンポーネントを破棄・再生成し、前回の入力内容や検索結果が新しいアイテムへ意図せずコピー・引き継がれる問題を解消。

### 5. 経路検索における2種別ルート（最速・乗換最少）提示とレイアウト最適化
- **2種別の最適化ルート提示**:
  - **① 最速（`⏱ 最速`）**: 所要時間が最も短いルート（`strategy: fastest`）
  - **② 乗換最少（`🔄 乗換最少`）**: 乗り換え回数が最も少ない（直通含む）ルート（`strategy: fewestTransfers`）
- **UI表示の最適化**:
  - 検索結果カード内に「所要時間（〇〇分）」と「乗換（〇回 / 直通）」を分かりやすく配置した2列メトリクスバーを採用。
  - Transit API の仕様に合わせ、提供されていない料金表示（¥0等）を完全に排除して正確かつクリーンな表示に統一。
- **バックエンド Transit API 連携 & モック両対応**:
  - バックエンドプロキシ（`fetch_transit_plan`）にて `fastest` と `fewestTransfers` の並列取得結果をタグ付きでマージして返却。
  - フロントエンドモック環境でも2パターンの差別化された経路データを即時提供。
